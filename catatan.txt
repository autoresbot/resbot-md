Solusi : ada 10 pilihan gaya video. Tulis nomornya setelah .jj, boleh

[BARU] Maker baru: .fakeff, .fakedana, .fakebca, .fakeovo, .fakegc,
       .spotifycard
File   : plugins/MAKER/fakeff.js, fakesaldo.js, fakegc.js, spotifycard.js
         (semua baru), lib/maker.js
Gejala : belum ada fitur untuk membuat gambar-gambar ini
Sebab  : -
Solusi : semua otomatis muncul di menu maker dan memotong 1 limit.
         Cara pakai:
         - .fakeff nama           -> template acak
           .fakeff nama | 3       -> pilih template 1 sampai 8
           Nama wajib diisi. Kalau kosong atau template di luar 1-8,
           bot membalas format: .fakeff nama | 1-8
         - .fakedana nama|50000   (tanpa nama = pakai nama WA)
         - .fakebca nama|50000    (tanpa nama = pakai nama WA)
         - .fakeovo 50000         (OVO hanya nominal, tanpa nama)
         - .fakegc nama grup | 1024 (alias .fakegrup). Nama dan jumlah
           member wajib diisi, kalau kosong / bukan angka bot membalas
           format
         - .spotifycard Judul|Artis (alias .fakespotify). Tanpa artis =
           nama WA
         - Foto .fakegc dan cover .spotifycard bisa diganti: kirim gambar
           dengan caption command, atau balas (reply) gambar / stiker.
           Tanpa gambar, .fakegc memakai foto grup (kalau di grup) atau
           foto profil pengirim, .spotifycard memakai foto profil
           pengirim
Catatan: - Nominal boleh ditulis 50.000 atau Rp50,000, titik/koma/Rp
           dibuang otomatis. Teks campuran huruf dan angka (mis. .fakedana
           budi123) tidak dianggap nominal - bot membalas format, bukan
           membuat gambar bernominal 123
         - Kalau API menolak (mis. template di luar 1-8), alasannya
           ditampilkan ke pengguna
         - Memakai APIKEY dari config, sama seperti maker lain


[BUG] .tiktok gagal dengan link vm.tiktok.com - "URL harus dari TikTok"
File   : lib/scrape/tiktok.js, plugins/DOWNLOAD/tiktok.js,
         plugins/DOWNLOAD/tiktok slide.js
Command: .tiktok, .tt, .ttslide, .tiktokslide
Gejala : link bagikan dari aplikasi TikTok (vm.tiktok.com/...) selalu
         gagal dengan pesan "URL harus dari TikTok", padahal linknya benar
Sebab  : API hanya menerima link www.tiktok.com dan vt.tiktok.com. Link
         vm.tiktok.com dan m.tiktok.com ditolak, padahal keduanya hanya
         link pendek yang diarahkan (redirect) ke www.tiktok.com/@user/
         video/<id>. Selain itu .tiktok mengirim SELURUH isi pesan ke API,
         bukan linknya saja, dan link tanpa https:// dianggap tidak valid
Solusi : sebelum ke API, link TikTok diambil dari pesan lalu redirect-nya
         diikuti sampai ke link www.tiktok.com/@user/video/<id> (atau
         /photo/<id>). Link akhir inilah yang dikirim ke API, tanpa
         tambahan ?_r=1&_t=... di belakangnya
Catatan: - Diuji: vm.tiktok.com, vt.tiktok.com, www.tiktok.com/t/...,
           m.tiktok.com/v/..., link lengkap, dan link tanpa https://
           semuanya berhasil
         - Kalau link pendek ternyata tidak mengarah ke video (salah ketik
           atau videonya sudah dihapus / private), bot membalas "Link
           TikTok tidak valid, atau videonya sudah dihapus / private"
         - .ttmp3 tidak diubah karena sumber datanya (tikwm) sudah bisa
           membaca link pendek sendiri


[BUG] .smeme gagal untuk gambar besar - "HTTP 413 - File too large"
File   : lib/uploader.js, lib/imageNormalizer.js, plugins/MAKER/smeme.js,
         plugins/MAKER/stickercircle.js
Command: .smeme, .stickercircle
Gejala : "❌ Gagal membuat sticker meme. HTTP 413 - File too large. Max 5 MB
         allowed." saat membalas foto HD atau screenshot berukuran besar
Sebab  : gambar harus diupload dulu ke server sebelum diproses, dan server
         upload hanya menerima file sampai 5 MB. .smeme dan .stickercircle
         mengupload gambar apa adanya tanpa diperkecil, jadi foto di atas
         5 MB langsung ditolak
Solusi : sebelum upload, gambar di atas 5 MB diperkecil dulu menjadi JPEG
         (sisi terpanjang maksimal 2048 px, turun ke 1600 / 1280 px kalau
         masih kebesaran). Gambar di bawah 5 MB dan sticker tetap dikirim
         apa adanya seperti sebelumnya
Catatan: - Diuji dengan PNG 12 MB: cara lama gagal dengan HTTP 413 yang
           sama, cara baru diperkecil jadi 2,5 MB lalu sticker meme
           berhasil dibuat
         - Berlaku otomatis juga untuk fitur lain yang mengonversi gambar
           sebelum upload (.hd, .removebg, .jj, dll)
         - .tovid, .toimg, dan .tourl tidak diubah, karena fitur itu harus
           mengirim file asli tanpa diubah formatnya


[BARU] .idch - cek ID saluran WhatsApp
File   : plugins/TOOLS/idch.js (baru)
Command: .idch, .cekidch, .idsaluran
Gejala : belum ada cara mendapatkan ID saluran (xxxx@newsletter), padahal
         ID ini dibutuhkan untuk fitur yang mengirim ke saluran
Sebab  : -
Solusi : ada dua cara pakai:
         - .idch https://whatsapp.com/channel/xxxx (boleh juga langsung
           ID ...@newsletter)
         - balas pesan yang diteruskan dari saluran dengan .idch
         Bot membalas ID saluran, nama, jumlah pengikut, status verifikasi,
         status saluran, tanggal dibuat, link, dan cuplikan deskripsi
         (satu baris, maksimal sekitar 100 huruf). Memotong 1 limit dan
         otomatis muncul di menu tools
Catatan: - Datanya diambil langsung dari WhatsApp lewat zapo-js, tanpa API
           key dan bot tidak perlu mengikuti salurannya
         - Cara balas pesan terusan tetap menampilkan ID dan nama saluran
           walaupun detail lainnya gagal diambil
         - Link salah atau saluran yang sudah dihapus dibalas "Saluran
           tidak ditemukan"

[BUG] Grup "pesan sementara": pesan yang di-reply tidak terbaca
File   : lib/utils.js, lib/serializeMessage.js, plugins/TOOLS/idch.js
Gejala : di grup yang menyalakan pesan sementara, semua command dengan
         cara reply bertingkah seolah tidak ada yang di-reply:
         - .kick / .promote / .demote / .delete / .ban tidak tahu targetnya
         - .sticker, .smeme, .hd, .jj, .rvo, .fakegc, .spotifycard dengan
           reply gambar dibalas "kirim/balas gambar"
         - autoai, autosimi, autorusuh tidak menanggapi reply ke pesan bot
         - .idch dengan reply pesan terusan saluran dibalas cara pakai
Sebab  : grup pesan sementara membungkus setiap pesan dalam satu lapis
         tambahan (ephemeralMessage). Perbaikan antilink di 5.4.5 sudah
         membuka lapis ini untuk teks pesan, tapi bagian yang membaca
         pesan yang di-reply masih membaca lapis paling luar saja
Solusi : lapis ephemeralMessage dibuka dulu sebelum pesan yang di-reply
         dibaca. Hanya lapis itu yang dibuka, jadi pesan di grup / chat
         biasa diproses persis seperti sebelumnya
Catatan: - Diuji dengan 11 jenis pesan (teks, link, reply teks, reply
           gambar, gambar + caption, mention, sekali lihat, pesan bot,
           terusan saluran, stiker): untuk pesan biasa hasil versi lama dan
           baru identik, untuk pesan sementara hasilnya sekarang sama
           dengan pesan biasa
         - Ikut diperbaiki: antibot sekarang mengenali pesan tombol dari
           bot lain di grup pesan sementara, dan pesan sekali lihat di
           grup itu kembali terbaca sebagai sekali lihat
