Update Resbot MD 5.4.2

Perbaikan .backup, .backuptele & backup otomatis
- error "Media upload failed on all hosts" tidak lagi muncul mentah. Kalau
  upload ke server media WhatsApp ditolak, bot mencoba ulang 3x (jeda 5, 15,
  dan 30 detik) sambil mengambil server media baru dulu
- sebelum diupload, file backup diperiksa dulu: ada / tidak kosong / tidak
  melebihi 90 MB. Kalau kebesaran, bot langsung memberitahu supaya folder
  tmp/ dan logs/ dikosongkan, atau pakai .backuptele
- isi zip lebih ramping: node_modules di dalam folder lain (mis. dashboard/)
  dan file .zip lama tidak ikut dibackup lagi
- laporan .backup sekarang merinci nomor mana yang berhasil menerima, mana
  yang gagal beserta alasannya, dan nomor mana yang dilewati
- setiap pesan gagal kini menyebut TAHAP (konfigurasi / buat zip / periksa
  file / siapkan tujuan / upload), PENYEBAB, dan SOLUSI-nya

Keamanan pengiriman backup di WhatsApp (cegah banned)
- nomor tujuan diperiksa dulu ke WhatsApp; nomor yang tidak terdaftar
  dilewati, jadi tidak ada pengiriman ke target yang salah
- nomor owner yang ditulis dua kali (atau sama dengan nomor bot) hanya
  dikirimi satu kali
- ada jeda acak 5-12 detik antar nomor, dan jumlah tujuan dibatasi 10 nomor
  per backup supaya tidak terlihat seperti blast
- kalau satu nomor gagal, nomor lain tetap dikirimi

Backup Telegram (.backuptele)
- token & chat id pindah ke config.js (TELEGRAM_BOT_TOKEN dan
  TELEGRAM_CHAT_ID), tidak lagi diisi di dalam file plugin
- kalau belum diisi, bot menampilkan panduan lengkap cara membuat bot di
  @BotFather dan cara mengambil chat id
- token/chat id yang salah format langsung ditolak dengan keterangan jelas,
  tanpa menunggu proses zip selesai
- koneksi ke Telegram diuji DULU sebelum file zip dibuat, jadi kalau token
  tidak valid atau chat tidak ditemukan, kegagalannya diketahui seketika
- kalau berhasil, bot menyebutkan nama chat/grup tujuannya

Backup otomatis (AUTO_BACKUP)
- kegagalan backup otomatis kini dilaporkan ke WhatsApp owner (satu nomor
  saja, supaya aman), dulu hanya lewat di log server
- ada opsi baru AUTO_BACKUP_TELEGRAM di config.js: bila true, hasil backup
  otomatis juga dikirim ke Telegram
- siklus backup tidak akan tumpang tindih kalau backup sebelumnya masih
  berjalan

  folder sementara sistem dan tidak pernah dihapus. Lama-lama penyimpanan
  panel penuh, lalu muncul error "ENOSPC: no space left on device"
- yang paling cepat kena adalah sticker animasi (.bratdeluxe, .bratcomic,
  .bratbubble, .bratneon, .bratword, .bratglitch) karena filenya paling

- sekarang file sticker langsung dihapus setelah terkirim, dan sisa

- berlaku untuk semua fitur sticker (.sticker, .brat, .qc, .smeme, dll)
- panel yang sudah terlanjur penuh: cukup restart server satu kali setelah
  update, sesudah itu tidak menumpuk lagi

Perbaikan .snakes (sering "Gagal mengambil gambar papan dari api")
- gambar papan kini dicoba sampai 3x (jeda 1 & 2 detik) sebelum menyerah,
  jadi gangguan jaringan sesaat tidak langsung bikin gagal
- kalau tetap gagal, PERMAINAN TIDAK BERHENTI: hasil lemparan dadu, posisi,

Perbaikan .sewabot, .tambahsewa, .sewabotid (sewa tercatat padahal gagal)
- sebelumnya kalau bot GAGAL masuk grup, kegagalannya diabaikan diam-diam
  lalu sewa TETAP tercatat di database. Akibatnya ada data sewa untuk grup
  yang botnya tidak ada di dalamnya
- sekarang sewa hanya dicatat setelah bot benar-benar berada di grup itu.
  Kalau gagal, bot menjawab "Sewa TIDAK dicatat"
- alasan gagalnya disebutkan: bot pernah dikeluarkan/diblokir, link sudah
  tidak berlaku, link tidak valid, grup penuh, butuh persetujuan admin,
  atau server tidak membalas
- .tambahsewa tidak lagi memperpanjang sewa kalau bot sudah tidak di grup
- .sewabotid tidak lagi mencatat sewa untuk ID grup yang botnya tidak ada
  di dalamnya (dulu tetap menjawab "Bot Sudah Bergabung"), dan sekarang
  menampilkan nama grupnya
- kalau bot memang sudah jadi anggota, sewa tetap bisa dibuat seperti biasa

Perbaikan .ping
- sebelumnya .ping <apa saja> sering gagal dengan pesan "Maaf, terjadi
  kesalahan saat melakukan ping" tanpa penjelasan apa pun
- sekarang bot menyebut alasannya: domain tidak ditemukan, koneksi ditolak,
  timeout, DNS bermasalah, sertifikat SSL kedaluwarsa, atau HTTP sekian
- ada batas waktu 10 detik, jadi tidak menggantung lama
- .ping <domain> kini benar-benar mengetes domain yang diketik. Dulu isinya
  diabaikan: .ping tiktok.com tetap menembak google.com lalu melaporkan
  google sebagai hasilnya
- .ping tanpa isi menampilkan lama bot aktif & jeda pesan (dulu selalu
  menampilkan angka ~0.000003 s yang tidak berarti apa-apa)

Perbaikan .setopengc & .setclosegc (bisa pakai teks sendiri)
- sekarang jam & teks diatur sekaligus:
  .setopengc 23:10                    -> pakai teks default
  .setopengc 23:10 Grup sudah dibuka  -> pakai teks sendiri
  .setopengc off                      -> hapus jadwalnya
- sama untuk .setclosegc
- teksnya bisa memakai variabel: @group, @size, @desc, @time, @date, @day,
  @greeting. Contoh: .setopengc 07:00 Selamat @greeting anggota @group
- balasan bot menampilkan jam + teks yang akan dipakai, jadi langsung
  kelihatan benar atau tidak
- keduanya tidak lagi menolak admin di grup dengan ID baru (LID)

Fitur Baru: .silent (hapus pesan + abaikan anggota tertentu)
- .silent @user            -> silent 30 menit (default)
- .silent @user 45m        -> silent 45 menit
- .silent @user 2h Toxic   -> silent 2 jam, dengan alasan
- .silent @user permanent Spam Chat -> silent selamanya
- bisa juga dengan membalas pesan targetnya: .silent 1d Spam
- format durasi: m (menit), h (jam), d (hari), permanent/perm/forever/0
- .unsilent @user  -> batalkan
- .listsilent      -> daftar yang sedang di-silent + sisa waktunya
- selama di-silent: setiap pesan orang itu DIHAPUS bot, dan semua
  command-nya DIABAIKAN (game, AFK, autoai, list, dll ikut diam)
- masa silent berakhir otomatis, tidak perlu di-unsilent manual
- khusus admin grup/owner. Admin grup & owner tidak bisa di-silent
- bot harus jadi admin grup supaya bisa menghapus pesan. Kalau bot bukan
  admin, pesannya tidak terhapus tapi tetap diabaikan

Fitur Baru: .autodelwelcome & .autodelleft (hapus otomatis pesan sapaan)
- pesan welcome/left bisa dihapus otomatis setelah sekian waktu, biar grup
  tidak penuh sapaan
- .autodelwelcome 10s / 30s / 1m / 5m -> atur durasi
- .autodelwelcome off  -> matikan
- .autodelwelcome cek  -> lihat status
- sama untuk .autodelleft
- maksimal 60 menit. Tanpa satuan dianggap detik (mis. .autodelwelcome 90)
- berlaku untuk semua tampilan (teks, gambar template, foto/video sendiri)
- catatan: kalau bot restart sebelum waktunya, pesan itu tidak jadi terhapus

Perbaikan .setwelcome & .setleft (lebih mudah + bisa foto/video sendiri)
- CUKUP balas foto/video/stiker sambil mengetik perintahnya, bot otomatis
  memakainya. Tidak perlu mengetik kata "foto" atau "video":
  .setwelcome Selamat datang @name   (sambil membalas foto/video/stiker)
  .setleft Selamat jalan @name       (sambil membalas foto/video/stiker)
- stiker diam otomatis diubah jadi gambar, stiker GERAK otomatis diubah
  jadi video (diputar berulang seperti GIF)
- pilihan tampilan lain:
  .setwelcome text <teks>                      -> hanya teks
  .setwelcome template <teks>                  -> gambar welcome (baru)
  .setwelcome template <1-7/random> <teks>     -> template lama
  .setleft text <teks> / .setleft template <teks>
- BARU: pesan perpisahan (.setleft) kini bisa bergambar juga — sebelumnya
  hanya teks. Ada gambar GOODBYE otomatis berisi foto profil & nama
- teks boleh dikosongkan saat ganti tampilan, teks lama tetap dipakai
- cara lama (.setwelcome Selamat datang @name tanpa media) tetap berfungsi:
  hanya mengganti teksnya, tampilan tidak berubah
- .setwelcome / .setleft tanpa isi menampilkan panduan + daftar variabel
- .teswelcome bisa diketik tanpa angka, dan .tesleft (baru) menampilkan
  pesan perpisahan sesuai setelan yang sedang dipakai
- video biasa dikirim sebagai video (ada suara, tidak berulang), GIF tetap
  dikirim sebagai GIF. Sebelumnya semua video ikut jadi GIF
- kalau gambar gagal dibuat atau filenya hilang, teksnya tetap dikirim
  (dulu bisa tidak muncul sama sekali)
- PENTING: dulu welcome/left DIAM TOTAL kalau teksnya belum pernah diisi,
  walaupun fitur sudah .on dan tampilan sudah diatur (padahal .teswelcome /
  .tesleft tetap tampil sehingga terlihat normal). Sekarang bot memakai teks
  bawaan kalau belum diatur
- saat beberapa orang masuk/keluar berbarengan, semuanya kini disapa.
  Dulu hanya orang pertama, sisanya terbuang karena batas 3 detik per grup
- keduanya tidak lagi menolak admin di grup dengan ID baru (LID)

Fitur Baru: .acc / .unacc (bot hanya aktif di grup yang diizinkan)
- mulai versi ini bot DIAM di semua grup: tidak membalas command dan tidak
  menjalankan fitur apa pun (antilink, welcome, list, game, notif sholat,
  buka/tutup grup otomatis, alarm, dll), sampai owner mengaktifkannya
- .acc -> ketik di grup untuk mengaktifkan bot di grup itu
- .unacc -> ketik di grup untuk menonaktifkannya lagi
- bisa juga dari chat pribadi dengan menyebut grupnya:
  .acc 120363xxxxxxxxx@g.us  atau  .acc 3 (nomor dari .listacc)
- .listacc -> daftar SEMUA grup yang diikuti bot, ditandai ✅ aktif /
  ❌ belum, lengkap dengan nomor urut & ID grup
- .accall -> aktifkan semua grup sekaligus
- .unaccall -> nonaktifkan semua grup. Grup sewa sengaja dilewati; kalau
  ingin ikut dimatikan ketik .unaccall sewa
- owner tetap bisa memakai bot di grup mana pun (termasuk untuk .acc)
- chat pribadi tidak terpengaruh
- terhubung dengan sewa: grup yang disewakan (.tambahsewa / .sewabot)
  otomatis aktif, dan kembali diam saat sewa habis atau dihapus
- grup yang sudah punya sewa sebelum update otomatis aktif, grup lainnya
  perlu di-.acc satu per satu oleh owner
- untuk pengguna baru: selama DATA_OWNER di config masih kosong, command
  .id bisa dipakai siapa pun (termasuk di grup yang belum di-.acc). Balasan
  .id menampilkan ID kamu beserta cara mengisinya ke DATA_OWNER. Setelah
  DATA_OWNER terisi & bot direstart, .id kembali mengikuti aturan biasa

Perbaikan .update (gagal "Request failed with status code 504")
- error 504 bukan dari server API autoresbot, tapi dari GitHub: file update
  diunduh dari GitHub, dan server GitHub kadang timeout saat menyiapkan file
  zip-nya. Sifatnya sementara
- sekarang download dicoba ulang otomatis sampai 3 kali (jeda 5 lalu 10
  detik). Owner diberi tahu di chat setiap kali bot mencoba lagi
- pesan gagal lebih jelas, contoh: "Server GitHub timeout (HTTP 504) saat
  menyiapkan file update", bukan lagi teks teknis
- download yang macet (tidak ada data 60 detik) dibatalkan dan dicoba lagi,
  tidak lagi menggantung tanpa kabar
- file hasil unduhan dicek dulu. File yang terpotong atau rusak tidak ikut
  dipasang, dan sisa file update yang gagal langsung dibersihkan

Perbaikan Tampilan Console
- pesan pemuatan fitur dan dashboard sekarang seragam dengan log lain: ada
  jam:menit dan warna, contoh:
    [10:13] System : Koneksi Terhubung
    [10:13] System : Handler & plugin dimuat (338 plugin)
    [10:13] Dashboard : Aktif di http://127.0.0.1:3000
- warna dashboard: hijau = aktif, kuning = tidak dijalankan (mis. port

Fitur Baru: Clone List Antar Grup (.idclone & .clonegc)
- sekarang list satu grup bisa disalin ke grup lain, tidak perlu ketik
  .addlist satu per satu
- caranya: di grup yang list-nya mau disalin, admin ketik .idclone. Bot
  memberi kode, misalnya K7FQX2
- lalu di grup tujuan, admin ketik .clonegc K7FQX2 dan semua list ikut
  tersalin
- .clonegc tanpa kode akan menampilkan cara pakainya
- kode berlaku 10 menit dan hanya bisa dipakai sekali. Kalau kedaluwarsa,
  tinggal minta lagi dengan .idclone
- keduanya hanya bisa dipakai admin grup (dan owner), di dalam grup
- list grup tujuan DIGABUNG, bukan diganti: list lama tetap ada, list dari
  grup sumber ditambahkan
- kalau ada keyword dengan nama sama, yang dipakai tetap milik grup tujuan
  (tidak ditimpa). Bot memberitahu berapa yang dilewati
- kalau memang ingin menimpa, tambahkan kata timpa:
    .clonegc K7FQX2 timpa
- gambar/video yang menempel di list ikut disalin sebagai file baru, jadi
  menghapus list di grup asal tidak merusak list hasil clone
- yang disalin hanya list. Setelan lain (welcome, antilink, badword, absen,
  dan lain-lain) tidak ikut

Perubahan: Tampilan .ping Dibuat Simple
- .ping sekarang hanya membalas satu baris:
    ⌬ Response Time : 0.000011 s
- .ping domain.com (misalnya .ping google.com) membalas dua baris:
    ⌬ Response Time : 0.145781 s
    ⌬ Ping : https://www.google.com
- info uptime, jeda pesan, dan status HTTP dihapus supaya balasannya ringkas
- kalau alamat tidak bisa dihubungi, bot tetap memberi alasan kegagalannya
