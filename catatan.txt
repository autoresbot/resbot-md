[BARU] .listdbgrub / .copylistid / .dellistid - kelola list grup lewat ID
File   : plugins/OWNER/list db grub.js
Command: .listdbgrub, .copylistid, .dellistid
Isi    : mengelola database LIST sebuah grup lewat ID-nya, berguna saat
         grup sudah TERBLOKIR sehingga bot tidak bisa menjalankan perintah
         di dalam grup itu. Khusus owner
         - .listdbgrub            -> tampilkan SEMUA grup yang masih punya list
                                     di database (ID + jumlah keyword + UKURAN
                                     + tgl update), diurutkan dari yang terbesar
                                     plus total semua grup. Ukuran = teks JSON
                                     list + file media (database/media) yang
                                     dirujuk tiap keyword. Dipakai untuk
                                     MENEMUKAN id grup terblokir tanpa harus
                                     masuk ke grupnya, sekaligus melihat grup
                                     mana yang paling makan ruang
         - .copylistid <idSumber> (di grup tujuan) atau <idSumber> <idTujuan>
         - .dellistid <idGrup>
Alur grup terblokir:
         1. .listdbgrub            -> catat id grup yang datanya masih ada
         2. .copylistid <id>       -> salin list-nya ke grup lain (penyelamatan),
            atau .dellistid <id>   -> hapus kalau memang mau dibuang

Update Resbot MD 5.4.7


RINGKASAN
=========
- Koneksi WhatsApp lebih stabil: 405 berulang, restart, dan logout
  sekarang ditangani dengan benar
- Request ke API tidak lagi sering gagal ETIMEDOUT / ENETUNREACH di
  panel tanpa IPv6
- .sewabot / .tambahsewa menjelaskan dengan jelas kalau nomor bot sedang
  dibatasi WhatsApp sehingga tidak bisa masuk grup lewat link
- .sewabot / .tambahsewa tidak lagi mencoba masuk grup kalau bot sudah
  ada di dalamnya (mis. dimasukkan manual oleh admin)
- .hd membalas "Server sedang sibuk, coba lagi sebentar" saat API gagal
- Jadwal sholat disimpan per kota per hari, tetap jalan saat API gagal


DETAIL
======

[BUG] Koneksi WhatsApp sering reconnect (405 / restart required)
File   : lib/connection.js
Gejala : bot terus-menerus reconnect, terutama setelah WhatsApp merilis
         versi WA Web baru
Sebab  : kode 405 (versi WA ditolak) tidak pernah dikenali, jadi bot
         reconnect terus dengan versi yang sama
Solusi : - versi WA Web terbaru diambil saat connect, dan diambil ulang
           setiap kali muncul 405. Kalau 405 terus berulang, bot
           menyarankan .updatezapo
         - restart required / koneksi putus -> reconnect setelah 3 detik
         - logout (401) -> berhenti reconnect dan menampilkan pesan untuk
           pairing ulang
         - socket lama ditutup dulu sebelum membuat yang baru, dan tidak
           ada dua reconnect yang berjalan bersamaan


[BUG] Request API gagal: connect ETIMEDOUT / ENETUNREACH
File   : lib/netBootstrap.js (baru), index.js
Gejala : request ke API (autoresbot dan lainnya) sering gagal dengan
         "connect ETIMEDOUT" atau "ENETUNREACH", terutama di panel yang
         tidak punya IPv6
Sebab  : Node 20 mencoba semua alamat IP (Happy Eyeballs) dengan batas
         hanya 250 ms per alamat. Saat bot sibuk (mis. sedang reconnect
         WhatsApp), batas itu terlewati sehingga semua alamat dianggap
         timeout
Solusi : alamat IPv4 dicoba lebih dulu dan batas per alamat dinaikkan
         jadi 2 detik
Catatan: berlaku otomatis untuk semua request HTTP di bot


[UBAH] Helper API bersama
File   : lib/apiClient.js (baru)
Gejala : -
Sebab  : -
Solusi : helper untuk memanggil API dengan timeout 15 detik dan retry 3x
         (jeda 1, 2, lalu 4 detik). Retry hanya dilakukan untuk error
         jaringan dan HTTP 5xx / 429. Setiap percobaan yang gagal
         dicatat di console: [API:<fitur>] percobaan n/4 gagal
Catatan: untuk saat ini baru dipakai oleh jadwal sholat dan .hd. Fitur
         lain tidak diubah


[BUG] .hd - API gagal tanpa pesan yang jelas
File   : plugins/TOOLS/hd.js
Command: .hd
Gejala : saat server API bermasalah, .hd gagal tanpa penjelasan
Sebab  : request hanya dicoba satu kali tanpa retry
Solusi : memakai lib/apiClient.js (otomatis retry). Kalau tetap gagal,
         pengguna dibalas "⏳ Server sedang sibuk, coba lagi sebentar."


[UBAH] Jadwal sholat - cache per kota per hari
File   : lib/features.js, plugins/ISLAMI/jadwal sholat.js, .gitignore
Command: .jadwalsholat dan pengingat waktu sholat otomatis
Gejala : jadwal sholat ikut gagal setiap kali API sedang bermasalah
Sebab  : jadwal diambil ulang dari API tanpa disimpan
Solusi : API dipanggil sekali per kota per hari, lalu hasilnya disimpan
         di database/jadwal_sholat_cache.json. Kalau API gagal, dipakai
         jadwal tersimpan yang terakhir
Catatan: - pengaturan retry lama (SHOLAT_RETRY) dihapus, diganti retry
           dari lib/apiClient.js
         - file cache dibuat otomatis dan tidak ikut ke git


[UBAH] .sewabot / .tambahsewa - pesan "account_reachout_restricted"
File   : lib/gabungGrup.js
Command: .sewabot, .tambahsewa
Gejala : .sewabot dibalas "Pesan dari server: group.joinViaInvite iq
         failed (463: account_reachout_restricted)" tanpa penjelasan
Sebab  : nomor bot sedang dibatasi WhatsApp (anti-spam), biasanya karena
         terlalu sering masuk grup / mengirim pesan dalam waktu singkat.
         Selama dibatasi, bot tidak bisa bergabung ke grup lewat link.
         Ini batasan dari WhatsApp, bukan kesalahan link atau bot
Solusi : pesan error diganti penjelasan dan solusinya: tunggu batasannya
         hilang sendiri (beberapa jam s/d beberapa hari), atau minta admin
         grup memasukkan bot secara manual lalu ulangi perintah tadi
Catatan: sewa tetap TIDAK dicatat selama bot gagal masuk grup


[BUG] .sewabot gagal walau bot sudah dimasukkan manual ke grup
File   : plugins/OWNER/sewabot.js, plugins/OWNER/tambah sewa.js,
         lib/gabungGrup.js
Command: .sewabot, .tambahsewa
Gejala : bot sudah dimasukkan manual oleh admin, tapi .sewabot tetap
         dibalas "Gagal bergabung ke grup" dan sewa tidak dicatat. Saran
         di pesan error (ketik .tambahsewa) juga tidak bisa dipakai karena
         .tambahsewa hanya untuk grup yang sewanya sudah tercatat
Sebab  : bot selalu mencoba masuk grup lewat link lebih dulu, walaupun
         sudah ada di dalamnya. Saat nomor bot dibatasi WhatsApp,
         percobaan itu gagal
Solusi : bot mengecek dulu apakah sudah ada di grup. Kalau sudah, sewa
         langsung dicatat tanpa mencoba masuk lagi. Pesan error sekarang
         menyarankan memasukkan bot manual lalu mengulangi perintah yang
         sama
